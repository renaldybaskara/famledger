# FinTrackr

A self-hosted, AI-powered personal finance tracker. Track spending, manage budgets, parse bank email receipts automatically, and get AI-generated insights — all on your own infrastructure with no external SaaS dependencies.

---

## Tech Stack

| Layer | Technology |
|---|---|
| Frontend | Expo Web (React Native Web) + NativeWind |
| API | NestJS 11, Drizzle ORM, Swagger |
| Background jobs | BullMQ workers |
| Database | PostgreSQL 16 + pgvector |
| Cache / Queue | Valkey 8 (Redis-compatible) |
| Object storage | MinIO |
| Local AI | Ollama (llama3.2:3b by default) |
| Reverse proxy | Caddy 2 (auto TLS) |
| Observability | Prometheus + Grafana + Loki + Promtail |
| Error tracking | GlitchTip (self-hosted Sentry) |
| Analytics | Plausible CE v2 |
| Uptime | Uptime Kuma |
| Auto-updates | Watchtower |

## Quick Start (Docker)

### Prerequisites

- Docker Engine 24+ with Compose V2
- 4 GB RAM minimum (8 GB recommended with Ollama)
- A domain name pointing to your server (for production TLS)

### 1. Clone and configure

```bash
git clone https://github.com/youruser/fintrackr.git
cd fintrackr
```

### 2. Run the setup script (recommended)

```bash
bash scripts/setup.sh
```

The script will:
- Generate `.env` with random secrets
- Build Docker images
- Start PostgreSQL and Redis, wait for readiness
- Run database migrations
- Seed default categories and settings
- Start all services
- Pull the Ollama LLM model (~2 GB download)

### 3. Manual setup (alternative)

```bash
# Copy and edit environment variables
cp .env.example .env
nano .env          # Set DOMAIN, CADDY_EMAIL, passwords

# Build images
docker compose build

# Start infrastructure
docker compose up -d postgres redis minio
sleep 15

# Run migrations
docker compose run --rm api node dist/scripts/migrate

# Start everything
docker compose up -d

# Pull Ollama model
docker compose exec ollama ollama pull llama3.2:3b
```

```bash

docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d \
```


## Environment Variables

Copy `.env.example` to `.env` and fill in the values. Key variables:

### Required in production

| Variable | Description |
|---|---|
| `DOMAIN` | Your server domain, e.g. `fintrackr.example.com` |
| `CADDY_EMAIL` | Email for Let's Encrypt TLS certificate |
| `JWT_SECRET` | 64-char random hex string (auto-generated by setup.sh) |
| `JWT_REFRESH_SECRET` | 64-char random hex string (auto-generated) |
| `POSTGRES_PASSWORD` | Database password (auto-generated) |
| `REDIS_PASSWORD` | Cache/queue password (auto-generated) |
| `MINIO_SECRET_KEY` | Object storage secret (auto-generated) |
| `ENCRYPTION_KEY` | 32-byte hex key for encrypting sensitive data |

### Optional

| Variable | Description |
|---|---|
| `GOOGLE_CLIENT_ID` | Google OAuth app client ID |
| `GOOGLE_CLIENT_SECRET` | Google OAuth app client secret |
| `GOOGLE_CALLBACK_URL` | OAuth redirect URI |
| `SMTP_HOST` | SMTP server for email notifications |
| `SMTP_USER` / `SMTP_PASS` | SMTP credentials |
| `OLLAMA_MODEL` | Ollama model name (default: `llama3.2:3b`) |
| `SLACK_WEBHOOK` | Slack webhook for Watchtower update notifications |
| `GRAFANA_USER` / `GRAFANA_PASSWORD` | Grafana admin credentials |
| `DISABLE_TIER_LIMITS` | Disable feature tier restrictions (default: `true`) |
| `TZ` | Timezone (default: `Asia/Jakarta`) |

## Pulling an Ollama Model

The default model is `llama3.2:3b` (~2 GB). To change it, set `OLLAMA_MODEL` in `.env`.

```bash
# Pull the default model
docker compose exec ollama ollama pull llama3.2:3b

# Use a larger model for better accuracy
docker compose exec ollama ollama pull llama3.2:8b

# List downloaded models
docker compose exec ollama ollama list

# Remove a model
docker compose exec ollama ollama rm llama3.2:3b
```

Available models: https://ollama.com/library

## Updating

### Manual update

```bash
# Pull latest images
docker compose pull

# Rebuild custom images (API, web)
docker compose build

# Restart with new images (zero-downtime rolling)
docker compose up -d
```

### Automatic updates (Watchtower)

Watchtower checks for image updates daily. It only updates containers with the label `com.centurylinklabs.watchtower.enable=true`. Your custom-built API and web images are NOT auto-updated (they require a rebuild).

To disable auto-updates entirely, remove the `watchtower` service from `docker-compose.yml`.

## Observability

### Grafana

Visit `http://grafana.your-domain.com` and log in with `GRAFANA_USER` / `GRAFANA_PASSWORD` from `.env`.

Pre-configured datasources:
- Prometheus (metrics)
- Loki (logs)

Import community dashboards from https://grafana.com/grafana/dashboards/ using these IDs:
- `1860` — Node Exporter Full
- `9628` — PostgreSQL Database
- `11835` — Redis / Valkey
- `13659` — MinIO

### Logs

All container logs are shipped to Loki via Promtail and queryable in Grafana's Explore view using LogQL.

```logql
# API errors
{service="api"} |= "ERROR"

# All logs from last 1 hour
{project="fintrackr"} | json | level = "error"

# Caddy access log for specific path
{service="caddy"} | json | uri =~ "/api/.*"
```

## Troubleshooting

### Services not starting

```bash
# Check all service status
docker compose ps

# View logs for a specific service
docker compose logs -f api
docker compose logs -f postgres

# Restart a single service
docker compose restart api
```

### PostgreSQL connection issues

```bash
# Check if postgres is healthy
docker compose exec postgres pg_isready -U fintrackr

# Check init.sql ran correctly
docker compose exec postgres psql -U fintrackr -c "\l"
```

### Ollama not responding

```bash
# Check Ollama logs
docker compose logs ollama

# Verify model is downloaded
docker compose exec ollama ollama list

# Pull model manually if missing
docker compose exec ollama ollama pull llama3.2:3b
```

### Caddy TLS issues

```bash
# Check Caddy logs
docker compose logs caddy

# Verify your domain resolves to your server IP
nslookup your-domain.com

# Check Caddy admin API
curl http://localhost:2019/config/
```

### Reset everything (destructive)

```bash
# Stop and remove all containers, volumes, and images
docker compose down -v --rmi local

# Then rerun setup
bash scripts/setup.sh
```

## Security Notes

- All internal services communicate on an isolated Docker bridge network (`internal`) with no direct host access
- Only Caddy is on the `public` network and listens on ports 80/443
- Never expose PostgreSQL, Redis, or MinIO ports in production (use `docker-compose.dev.yml` for local access only)
- Rotate secrets in `.env` periodically and restart services: `docker compose up -d`
- The `node-exporter` service uses `network_mode: host` to see real host metrics — restrict Prometheus access accordingly
- GlitchTip open registration is disabled by default (`ENABLE_OPEN_USER_REGISTRATION=false`)
- Plausible registration is set to `invite_only` by default
